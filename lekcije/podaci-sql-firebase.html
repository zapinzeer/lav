Deo 1Part 1 · šta su podaciwhat data is

Šta su podaci i čemu služe baze?What is data and what are databases for?

Podatak je zapisana činjenica: ime učenika, ocena, cena, datum. Sam po sebi podatak malo znači, a kad ga povežemo sa značenjem („Ana ima 5 iz fizike”) dobijamo informaciju. Baza podataka je organizovano mesto na kome se podaci čuvaju tako da ih možemo brzo naći, menjati i brisati, i da se ne izgube kad se program ugasi.

A piece of data is a recorded fact: a student name, a grade, a price, a date. On its own a piece of data means little, but once we link it to a meaning ("Ana has a 5 in physics") we get information. A database is an organised place where data is kept so we can find, change and delete it quickly, and so that it is not lost when a program is closed.

Zašto ne bismo sve držali u običnom tekstualnom fajlu ili Excel tabeli? Za malo podataka može. Ali kad podatke koristi mnogo ljudi odjednom, kad ih ima mnogo, ili kad moraju da budu tačni i povezani, treba nam sistem koji se brine o tome: sistem za upravljanje bazom podataka (DBMS).

Why not keep everything in a plain text file or a spreadsheet? For a little data you can. But when many people use the data at once, when there is a lot of it, or when it must be correct and linked together, we need a system that takes care of that: a database management system (DBMS).

Almost everywhere: the school register, a social media account, messages, a purchase in a shop, search history, a playlist. Behind almost every app there is a database.

Deo 2Part 2 · tabele i ključevitables and keys

Tabele, redovi, kolone i ključeviTables, rows, columns and keys

U relacionoj bazi podaci žive u tabelama. Tabela opisuje jednu vrstu stvari, na primer učenike. Svaka kolona (polje) je jedna osobina: ime, razred, e-pošta. Svaki red (zapis) je jedna konkretna stvar: jedan učenik. Presek reda i kolone je jedna vrednost.

In a relational database data lives in tables. A table describes one kind of thing, for example students. Each column (field) is one property: name, class, e-mail. Each row (record) is one concrete thing: one student. Where a row and a column cross there is a single value.

Tabela uceniciTable ucenici (students)
idimerazredemail
1Ana2Bana@skola.rs
2Marko2Amarko@skola.rs
3Jovana2Bjovana@skola.rs

Primarni ključ je kolona (ovde id) čija je vrednost različita u svakom redu, pa jednoznačno određuje red. Ime ne može da bude ključ, jer dva učenika mogu da se zovu isto. Strani ključ je kolona koja čuva primarni ključ iz druge tabele i tako povezuje tabele.

A primary key is a column (here id) whose value is different in every row, so it identifies the row unambiguously. A name cannot be a key, because two students may have the same name. A foreign key is a column that stores the primary key from another table and so links the tables.

Tabela oceneTable ocene (grades)

11Fizika5
21Informatika4
33Fizika3

Kolona ucenik_id je strani ključ: vrednost 1 znači „učenik sa id = 1”, dakle Ana. Zahvaljujući tome ime „Ana” ne moramo da ponavljamo u svakoj oceni; ako se promeni na jednom mestu, promenjeno je svuda.

The column ucenik_id is a foreign key: the value 1 means "the student with id = 1", that is Ana. Thanks to this we do not have to repeat the name "Ana" in every grade; if it changes in one place, it is changed everywhere.

Svaka kolona ima i tip: ceo broj (INTEGER), tekst (TEXT), datum (DATE), logička vrednost. Baza odbija vrednost pogrešnog tipa, što čuva podatke od grešaka.

Every column also has a type: a whole number (INTEGER), text (TEXT), a date (DATE), a true/false value. The database refuses a value of the wrong type, which protects the data from mistakes.

Deo 3Part 3 · osnove SQL-aSQL basics

SQL: razgovor sa bazomSQL: talking to a database

SQL (Structured Query Language) je jezik kojim tražimo od relacione baze da nešto pročita ili promeni. Naredbe liče na rečenice na engleskom. Ključne reči se po dogovoru pišu velikim slovima, a naredba se završava tačkom i zarezom.

SQL (Structured Query Language) is the language we use to ask a relational database to read or change something. The statements look like English sentences. By convention keywords are written in capitals, and a statement ends with a semicolon.

SELECT

SELECT bira kolone, FROM kaže iz koje tabele. Zvezdica znači „sve kolone”.

SELECT chooses columns, FROM says which table. The star means "all columns".

SELECT * FROM ucenici;
SELECT ime, razred FROM ucenici;

WHERE

WHERE zadržava samo redove koji ispunjavaju uslov. Uslovi se spajaju sa AND i OR, a redosled se zadaje sa ORDER BY. Tekst ide pod jednostrukim navodnicima.

WHERE keeps only the rows that meet a condition. Conditions are combined with AND and OR, and the order is set with ORDER BY. Text goes in single quotes.

SELECT ime FROM ucenici WHERE razred = '2B';
SELECT * FROM ocene WHERE predmet = 'Fizika' AND ocena >= 4;
SELECT * FROM ocene ORDER BY ocena DESC;

INSERT

INSERT INTO dodaje novi red. Navedemo kolone, pa vrednosti istim redom.

INSERT INTO adds a new row. We list the columns and then the values in the same order.

INSERT INTO ucenici (id, ime, razred, email)
VALUES (4, 'Luka', '2A', 'luka@skola.rs');

UPDATE

UPDATE menja vrednosti, a SET kaže šta se menja. Uvek stavi WHERE: bez njega se menjaju svi redovi u tabeli.

UPDATE changes values, and SET says what changes. Always add WHERE: without it every row in the table is changed.

UPDATE ucenici SET razred = '3A' WHERE id = 2;

DELETE

DELETE FROM briše redove. Ista opasnost: bez WHERE nestaje cela tabela sadržaja.

DELETE FROM removes rows. The same danger: without WHERE the whole content of the table disappears.

DELETE FROM ocene WHERE id = 3;
Pomisli prvo: šta radi naredba DELETE FROM ocene; bez WHERE?Think first: what does DELETE FROM ocene; do without WHERE?

Briše sve redove iz tabele ocene. Tabela ostaje, ali je prazna. Zato pre UPDATE i DELETE proveri uslov običnim SELECT-om sa istim WHERE.

It removes every row from the grades table. The table stays, but it is empty. So before UPDATE and DELETE, check the condition with a plain SELECT using the same WHERE.

Deo 4Part 4 · spajanje tabelajoining tables

JOIN: spajanje tabela preko ključaJOIN: linking tables through a key

Podaci su podeljeni u više tabela, a često nam trebaju zajedno: ime učenika i njegove ocene. JOIN spaja redove dve tabele kad se strani ključ poklopi sa primarnim. Uslov spajanja piše se iza ON.

Data is split across several tables, but we often need it together: a student name and their grades. JOIN pairs up rows of two tables when a foreign key matches a primary key. The joining condition is written after ON.

SELECT ucenici.ime, ocene.predmet, ocene.ocena
FROM ocene
JOIN ucenici ON ocene.ucenik_id = ucenici.id;
RezultatResult
imepredmetocena
AnaFizika5
AnaInformatika4
JovanaFizika3

Marko nema nijednu ocenu, pa ga nema u rezultatu: obični JOIN (INNER JOIN) prikazuje samo parove koji se poklapaju. Kad bismo hteli sve učenike, i one bez ocena, koristili bismo LEFT JOIN. Ispred imena kolone piše se ime tabele (ucenici.ime) kad bi inače bilo nejasno.

Marko has no grades, so he does not appear in the result: a plain JOIN (INNER JOIN) shows only pairs that match. If we wanted all students, including those without grades, we would use LEFT JOIN. The table name is put before the column name (ucenici.ime) when it would otherwise be unclear.

Deo 5Part 5 · Firebase kao servisFirebase as a service

Firebase Realtime Database kao servis za podatkeFirebase Realtime Database as a data service

Bazu ne moramo sami da instaliramo i održavamo. Firebase (Google) nudi bazu kao servis u oblaku: napraviš projekat, dobiješ adresu baze, a stranica u pregledaču čita i piše podatke preko interneta. Zato odmah radi na svakom uređaju, a promene se vide kod svih za deliće sekunde.

We do not have to install and maintain a database ourselves. Firebase (Google) offers a database as a cloud service: you create a project, get the address of the database, and a web page reads and writes data over the internet. So it works on every device at once, and changes show up for everyone within a fraction of a second.

Realtime Database ne koristi tabele. Podaci su jedno veliko JSON drvo: čvorovi sa ključevima i vrednostima, gde vrednost može da bude broj, tekst, tačno/netačno ili novi čvor sa podacima. Svaki čvor ima putanju, na primer /ucenici/ana/razred.

Realtime Database does not use tables. The data is one big JSON tree: nodes with keys and values, where a value can be a number, text, true/false, or another node holding more data. Every node has a path, for example /ucenici/ana/razred.

{
  "ucenici": {
    "ana":   { "razred": "2B", "ocene": { "fizika": 5, "informatika": 4 } },
    "marko": { "razred": "2A" }
  }
}

Upoređenje sa SQL-om: tabela je otprilike čvor ucenici, red je čvor ana, a kolone su njegova polja. Razlika je što ovde ocene mogu da žive unutar učenika, bez posebne tabele i JOIN-a. Drvo je brzo za čitanje onoga što je upakovano zajedno, ali se teže pretražuje na više načina.

Compared with SQL: a table is roughly the node ucenici, a row is the node ana, and the columns are its fields. The difference is that here the grades can live inside the student, with no separate table and no JOIN. A tree is fast for reading what is packed together, but harder to search in many different ways.

import { initializeApp } from "firebase/app";
import { getDatabase, ref, set, get, onValue } from "firebase/database";

const app = initializeApp({ apiKey: "...", databaseURL: "https://moj-projekat-default-rtdb.firebaseio.com" });
const db  = getDatabase(app);

await set(ref(db, "ucenici/luka"), { razred: "2A" });      // upis
const snap = await get(ref(db, "ucenici/luka"));            // čitanje
console.log(snap.val());                                   // { razred: "2A" }

onValue(ref(db, "ucenici"), s => console.log(s.val()));     // uživo

Pozivi su asinhroni: odgovor stiže kasnije, pa se koristi await ili povratna funkcija. push pravi jedinstven ključ (kao automatski id), pa dva korisnika koja istovremeno dodaju poruku ne prepisuju jedan drugog.

The calls are asynchronous: the answer arrives later, so we use await or a callback. push makes a unique key (like an automatic id), so two users adding a message at the same moment do not overwrite each other.

Deo 6Part 6 · pravila i bezbednostrules and security

Pravila baze: ko sme šta da čita i pišeDatabase rules: who may read and write what

Adresa Firebase baze i apiKey nalaze se u kodu stranice, pa ih svako može videti. Zato ne štite podatke. Zaštitu daju pravila bezbednosti (security rules), koja se čuvaju na serveru i odlučuju ko sme da .read (čita) i .write (piše), i koje vrednosti su ispravne (.validate). Pravila se pišu po putanjama, a važe i za sve ispod njih.

The address of a Firebase database and the apiKey sit in the code of the page, so anyone can see them. They do not protect the data. Protection comes from security rules, which are stored on the server and decide who may .read and .write, and which values are valid (.validate). Rules are written per path and apply to everything below them.

{
  "rules": {
    "javno": {
      ".read": true,
      ".write": false
    },
    "poruke": {
      ".read": true,
      "$id": {
        ".write": "auth != null",
        ".validate": "newData.child('tekst').isString() && newData.child('tekst').val().length <= 200"
      }
    }
  }
}

Ovde svako sme da čita javno, ali niko ne sme da piše. U poruke svako čita, a piše samo prijavljen korisnik (auth != null), i samo ako je tekst niz znakova do 200 znakova. $id je zamena za bilo koji ključ.

Here anyone may read javno (public), but nobody may write. In poruke (messages) anyone reads, and only a signed-in user writes (auth != null), and only if tekst is a string of up to 200 characters. $id stands for any key.

Pravilo ".read": true, ".write": true znači „svi mogu sve”. Dobro je za brzu probu, ali nikad za pravu aplikaciju. Tajni podaci (lozinke, privatne poruke) ne smeju u bazu koja je javno čitljiva.

The rule ".read": true, ".write": true means "everyone can do everything". It is fine for a quick test, but never for a real app. Secret data (passwords, private messages) must not go into a database that anyone can read.

Deo 8Part 8 · paziwatch out

Česte greškeCommon mistakes

  • UPDATE ili DELETE bez WHERE. Menja ili briše sve redove. Prvo proveri uslov sa SELECT.
  • Ime kao primarni ključ. Imena se ponavljaju. Koristi id koji je jedinstven.
  • Navodnici. U SQL-u tekst ide pod jednostrukim navodnicima, brojevi bez njih.
  • „Firebase je tabela.” Realtime Database je JSON drvo; nema redova, kolona ni JOIN-a.
  • Pravila „sve dozvoljeno”. Svako sa adresom baze može da je promeni ili obriše.
  • Očekivanje trenutnog odgovora. Pozivi ka Firebase-u su asinhroni, pa se rezultat koristi tek posle await ili u povratnoj funkciji.
  • UPDATE or DELETE without WHERE. It changes or removes every row. Check the condition with a SELECT first.
  • A name as the primary key. Names repeat. Use an id, which is unique.
  • Quotes. In SQL text goes in single quotes, numbers without.
  • "Firebase is a table." Realtime Database is a JSON tree; it has no rows, columns or JOIN.
  • "Allow everything" rules. Anyone with the database address can change or wipe it.
  • Expecting an instant answer. Firebase calls are asynchronous, so the result is used only after await or in a callback.

Deo 9Part 9

SažetakSummary

  • Podatak je zapisana činjenica; baza ih čuva organizovano, trajno i deli sa mnogo korisnika.
  • Relaciona baza: tabele sa kolonama (osobine) i redovima (zapisi); primarni ključ jednoznačno određuje red, strani ključ povezuje tabele.
  • SQL: SELECT čita, WHERE filtrira, INSERT dodaje, UPDATE menja, DELETE briše; UPDATE i DELETE uvek sa WHERE.
  • JOIN spaja tabele kad se strani ključ poklopi sa primarnim.
  • Firebase Realtime Database je servis u oblaku: JSON drvo sa putanjama; get, onValue, set, push, update i remove.
  • Zaštitu daju pravila (.read, .write, .validate), a ne skrivanje adrese baze.
  • Data is a recorded fact; a database keeps it organised, permanent and shared among many users.
  • A relational database: tables with columns (properties) and rows (records); a primary key identifies a row, a foreign key links tables.
  • SQL: SELECT reads, WHERE filters, INSERT adds, UPDATE changes, DELETE removes; always use WHERE with UPDATE and DELETE.
  • JOIN links tables when a foreign key matches a primary key.
  • Firebase Realtime Database is a cloud service: a JSON tree with paths; get, onValue, set, push, update and remove.
  • Protection comes from rules (.read, .write, .validate), not from hiding the database address.
